# Release host

`runRelease` drives the core release machine through scoped XState actors. The executor CLI exposes the same driver beside `train`.

```sh
pnpm executor release ready ./release.json --state .piper-release

PIPER_LIVE_ADMITTED_REPO=sample/project pnpm executor release fire ./release.json \
  --state .piper-release --verdicts ./verdicts.tsv --mode live \
  --by operator --verdict approve --words 'I approve this code-only plan.'
```

`fire` defaults to `--mode dry-run`. A dry fire records the first would-do intent and finishes without executing it. It does not simulate a successful deployment. `ready` runs the configured plan and preflight commands and writes READY. Neither mode constructs live message, page or verdict sinks. Manual checks should use `printOnlyReleaseLayer`. Plan and preflight commands must be read-only. Piper fences its sink services; it cannot inspect arbitrary configured executables.

A held review needs both `--override` and an `input.overrideBy` matching `--by`. `--words` supplies the operator's reason. The run log retains the admission and the override event. No operator words are generated by the driver.

## Configuration

Import `ReleaseConfigSchema` from `@joelhooks/piper-executor/release-domain`. All commands belong to the configuration. Piper supplies no provider-specific deployment command.

| Field | Contract |
| --- | --- |
| `name` | Release display name. |
| `repo` | Exact repository admitted by `PIPER_LIVE_ADMITTED_REPO`. |
| `predecessor` | Must be `accepted` for preparation and fire. |
| `preflight` | `{ command, args }`; exit zero establishes OK. |
| `commands` | Command dictionary described below. |
| `rowPrefix` | Prefix added to verdict evidence by the file sink. |
| `input` | Core `ReleaseInputSchema`, with extended checks. |
| `input.checks` | Nonempty list of distinct `{ name, onFail, everyMs, timeoutMs }` values. Timing values are positive integer milliseconds. |
| `input.expectation` | Configured code-only boundary. Use narrow allowed matchers, including resource ids or attributes. |
| `input.target` | Commit being released; stored as READY's `sha`. |
| `input.runId` | Stable release identity used in intent ids. |
| `input.windowEndsAt` | Absolute epoch milliseconds. Set an actual admitted release window. |
| `input.observationTimeoutMs` | Overall observation limit after deployment. |

The remaining input fields retain their core meanings: `allowAbsentReview`, `at`, `blackoutUntil`, `docs`, `minimumRunwayMs`, `previousTarget`, and optional `overrideBy`. Fire replaces `at` with the service clock. Checks keep their core `onFail` policy.

Preparation rejects any expectation violation. It also rejects resource actions other than `update` or `noop`, and kinds other than `resource`, `computed` or `deferred`. The expectation must identify which resource updates are code-only; an unrestricted resource-update matcher cannot distinguish code from infrastructure.

Every command has `command: string` and `args: string[]`. The executor appends arguments without a shell:

| Dictionary key | Added arguments / output |
| --- | --- |
| `PlanRelease` | `--target <sha>`; stdout is a JSON array of core release rows. |
| `Deploy` | `--target <sha>`. |
| `Restore` | `--target <previousTarget>`. |
| `Observe:<name>` | Baseline: `--check <name> --baseline`, stdout JSON `{ "outcome": "pass" | "fail" | "unknown" }`. Observation: `--check <name>`, with the last stdout line containing JSON `{ "outcome": "pass" | "fail" | "unknown" | "breach", ...detail }`. |
| `NotifyOwner` | `--cause <cause>`, plus `--check <name>` when present. |
| `MessageOwner` | One positional message string. Live fire only. |
| `PageOwner` | One positional page string. Live fire only. Put any page-marker operation behind this configured command. |

Observation detail survives in the logged observed event and verdict evidence. Diagnostic lines before the final observation JSON are allowed. Baseline and plan output remain JSON-only for compatibility with `executeRelease`.

## Refusals and records

`ReleaseRefusalSchema` defines tagged refusals. Every variant requires `harm` and `next`: configuration, predecessor, plan, preflight, READY, admission, deploy attempted, storage and execution. Config and operator-admission decoders collect all schema issues and name their sorted, deduplicated paths in both advice fields. They never include rejected values. Train and release share the path-only issue extractor; malformed JSON names the configuration root.

READY contains `{ sha, planHash, rows }`. The hash is SHA-256 of the schema-decoded plan rows. Fire requires the same commit and plan, then verifies the executed plan again before review or deployment.

Use one canonical state directory for a release. Do not copy READY into a fresh directory to evade an attempted deployment. Preserve the state directory when reconciling a crash.

The file store holds an exclusive scoped `release.lock`. It appends and syncs each JSONL record before proceeding. A Deploy intent is recorded **before** invoking the deploy command. Any recorded Deploy for that target refuses another fire, including a claim without an outcome. File syncs qualify process-crash recovery only; power-loss and remote-filesystem durability remain unqualified.

`RunLogLineSchema` owns the JSONL wire format:

| Tag | Payload |
| --- | --- |
| `intent` | `intent` |
| `outcome` | `id`, `outcome` |
| `event` | `event` |
| `admission` | `admission`, including `by` and `words` |
| `state` | `state` |
| `finished` | `state` |
| `would-do` | Existing executor `record` |
| `said` | `at`, `said`, `wake`: a successful live message and whether it paged |
| `message-failed` | `at`, `said`, `wake`, `error`: an unsuccessful live message attempt |

The live layer requires both MessageOwner and PageOwner commands before it opens its verdict file. Each successful live send appends a timestamped `said` record; failed sends append `message-failed` instead. These records preserve what the operator was told without treating a failed send as delivered. The tagged log format replaces the private host's format; it does not claim byte compatibility.

State changes send `release <name> <sha8>: <state>`. Completion sends `finished: <state>`. `held` and `escalated` also page. NotifyOwner failure stays in the outcome log and never stops finishing. A different intent failing without events stops execution with a refusal and a finish record.

## Observation lifecycle

The driver's graph owns admission, preparation, planning, review, override, fire, baseline, deploy, observation, restoration, notification, completion and paging. Each invoked task performs one stage's effects. Guarded `onDone` transitions inspect typed outcomes and core snapshots; tasks never choose a destination. Context stores executed intent ids and the persisted domain snapshot, not a route or a second current-state string.

Its reachable final states are `accepted`, `armed`, `escalated`, `held`, `ready`, `refused`, `rehearsed`, `restored` and `reviewHeld`. `runRelease` reads its result state from the driver's final snapshot. Preparation therefore returns `ready`, and dry fire returns `rehearsed`. Refusals fail the Effect rather than returning a successful result. Completion messages and log records still name the core state, including `planned` for a dry fire.

Under observing, a parallel machine creates one region per unsettled check. Each region owns a check machine with `waiting`, `sampling`, `settled` and `expired` states. Its cadence and deadline do not delay other regions. Settled checks are not sampled again. Per-check expiration cancels that check's command; the overall deadline steps `tick` into core, which escalates and pages if health remains unknown.

`VerdictSink` accepts only pass, fail and breach. The file layer writes one TSV row per `(sha, check)` and reloads those keys when reopened:

```text
ts<TAB>sha<TAB>step<TAB>outcome<TAB>rowPrefix+evidence
```

Tabs and line breaks inside cells become spaces. `makeVerdictMemory` provides an inspectable deduplicating test layer. `MessageSink`, `RunLog`, `ReadyStore` and Effect's `Clock` are replaceable services.

## Verification receipt

`test/release-run.test.ts` covers refusal advice, acceptance, held review, explicit override words, restoration after fail/breach, independent cadence and deadlines, unknown expiry, notification failure, eventless intent failure, deploy-attempt refusal, plan drift, durable rows and dry-run isolation. It observes actual driver snapshots across all nine final outcomes and asserts that context has no lifecycle routing fields. Path-diagnostic tests cover JSON config, typed config and operator admission, including a secret-looking synthetic wrong value and schema issues that retain their input.

Mutation checks were run before trusting the suite:

- Redirecting the accepted graph edge to armed failed the final-outcome trace. Reintroducing a context state string independently failed its context-shape assertion. Both faults were restored.
- Appending the raw schema message when issues retained input exposed the synthetic secret and failed the refusal test. Truncating the path list independently dropped `preflight.args` and failed the all-path assertion. Both faults were restored.

- A batch of narrow planted faults made all 18 initial host tests fail. Faults removed settled verdict delivery, pages, per-check limits, the deploy-attempt guard, override words, refusal advice, the changed-plan guard and memory deduplication. It also inverted eventless-failure handling, removed the dry-run service override, renamed the final driver state and admitted live sinks during rehearsal. All faults were restored.
- Inverting the settled-only row guard made the unknown-expiry test write unknown verdicts and fail. The guard was restored.
- Independently removing file deduplication produced four rows instead of one across reopening. The row test failed, then passed after restoration.
- Suppressing successful message receipts left the `said` records empty and failed the live message test. Restoring the append preserved the service-clock timestamp, message text and wake flag.
- Suppressing the observer failure signal made the typed storage-failure test return an ordinary escalated result instead of its refusal. Restoring the signal preserved typed failure and cancelled sibling checks.
- The CLI isolation test failed against a planted live-sink construction fault: dry fire created the real verdict file. Restoring the live-fire-only condition removed that file write. The test also caught and fixed a required Boolean override flag; ordinary approval does not require `--override`.

The CLI test launches only synthetic commands in a scoped temporary directory. No live release configuration is included.
